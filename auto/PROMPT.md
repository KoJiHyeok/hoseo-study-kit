# 매일 마감·제출 상태 점검 (자동 실행 — 헤드리스 `claude -p`)

너는 총괄이다. 사람이 보고 있지 않다. **변화가 없으면 아무것도 하지 마라** — 커밋도, 알림도.

작업 루트 = 현재 디렉터리(repo 루트). 파이썬은 맥 `python3`, Windows `python`.
과목·LMS 주소·course id 는 **`config.json` 이 정본**이다. 먼저 읽어라.

## 1. 최신화

```
git pull --rebase
```
충돌하면 **거기서 멈추고** 4번의 실패 보고로 간다. 억지로 풀지 마라.

## 2. LMS 스캔 — `aside` 로 한다

브라우저 툴(Chrome 확장 등)을 쓰지 말고 Bash/PowerShell 로 `aside` 를 호출한다. Aside 가 사용자 로그인과 **저장된 비밀번호**를 들고 있다.

### 2-0. 로그인부터 — LMS 세션은 하루를 못 넘긴다

`aside` 호출의 **첫 단계로 반드시** 아래를 넣는다 (`<lms_base>` 는 config.json 값):

> `<lms_base>/login/index.php` 를 열어라. 이미 로그인돼 있으면 넘어가라. 로그인 페이지가 뜨면 **브라우저에 저장된 아이디·비밀번호(자동완성)** 로 로그인 버튼을 눌러라. 자동완성되지 않으면 **추측하거나 입력하지 말고** '저장된 비밀번호 없음' 이라고 보고하고 멈춰라.

### 2-0-1. 만료되면 다시 로그인하고 재시도 — 바로 포기하지 마라

- 스캔 도중 어떤 페이지든 `login/index.php` 로 튕기면 → 그 자리에서 다시 로그인하고 **그 페이지부터 이어서** 읽는다. (aside 지시문에 이 문장을 그대로 넣어라.)
- 로그인 버튼을 눌렀는데 여전히 로그인 페이지면 → 5초 쉬고 다시, **최대 3회.**
- `aside` 호출이 끊기면 한 번 더 호출한다. 그래도 안 되면 Aside 앱을 켜고 20초 기다려 마지막으로 한 번 더.
- **실패로 치는 건 둘뿐**: ① 비밀번호 자동완성 안 됨 ② 재시도를 다 쓰고도 로그인 페이지. 이때만 4번 실패 보고로 간다.

### 2-1. 스캔

**한 번의 `aside` 호출**로 config.json 의 모든 과목(`lms_id`)을 처리한다 (과목별로 쪼개지 마라 — 느리다).
각 강좌의 **과제(`mod/assign`)와 퀴즈(`mod/quiz`)** 에서 받을 것: 과목 · 항목명 · 종류 · 마감일시 · 제출(응시) 여부.
같은 호출에서 각 강좌의 **온라인출석부**(동영상별 출결 O/X)도 읽어 과목 · 영상 제목 · 학습기간 종료일시 · 출결을 받는다. 재생 버튼은 누르지 마라.

### ⛔ aside 에게 반드시 그대로 전달할 제약

- **퀴즈의 '응시 시작' / 'startattempt' 버튼·링크를 절대 누르지 마라.** 응시 기회는 되돌릴 수 없다.
- **과제 제출 버튼을 누르지 마라.** 읽기만 해라.
- 로그인은 **저장된 비밀번호 자동완성 + 로그인 버튼** 까지만.

### ⚠️ 로그인 만료를 "항목 0건" 으로 착각하지 마라

`aside` 가 로그인 페이지에 머물렀다고 하거나 항목을 하나도 못 찾았다고 하면, 그건 "과제가 없다" 가 아니라 **"확인을 못 했다"** 이다.
파일을 고치지 말고 4번 실패 보고로 가라. 할일 파일을 "없음" 으로 덮어쓰면 절대 안 된다.

## 2.5 강의자료 수집 — 스크립트가 한다

2번 스캔이 **로그인 성공으로 끝난 뒤에만**:

```
python auto/fetch_materials.py
```

- 마지막 줄 JSON `{"login": …, "new": […], "skipped": […], "errors": […]}`.
- 종료코드 2(로그인 만료) → aside 로 재로그인 후 **한 번만** 다시. 그래도 2면 자료 수집만 포기하고 나머지는 진행.
- `new` 가 있으면 그것도 "변화"다. 자료 파일·원장을 직접 고치지 마라. 요약·시험지를 쓰지 마라(과목 에이전트 몫).

## 3. 변화가 있을 때만 반영

`<과목폴더>/할일/<NN>주차.md` 를 LMS 상태와 대조한다. 아래 중 하나라도 있으면 "변화"다.

1. **신규** — 할일 파일에 없는 과제·퀴즈가 열렸다
2. **제출됨** — 파일엔 `- [ ]` 인데 LMS 는 완료 → `- [x]`
3. **마감 변경** — `마감 MM-DD HH:MM` 이 LMS 와 다르다
4. **영상 시청** — 출결 O → `- [x]` + `시청 완료` / 기간 지났는데 X → 상태만 `미시청(기간 종료)`
5. **새 자료** — 2.5번이 파일을 저장했다

할일 파일 규칙: 항목은 **한 줄** `<무엇> — 마감 MM-DD HH:MM · <상태>`. 하위 불릿 금지. 주차 = 과제가 **나온** 주 = `(날짜 - semester_start) // 7 + 1`. 새 주차면 frontmatter(`course`, `week`, `created`, `sources`)를 넣어 만든다. **이미 `[x]` 인 항목을 되돌리지 마라.** 요약·시험지는 건드리지 않는다.

변화가 없으면 → `auto/last-run.log` 에 `no-change` 만 적고 끝낸다.

## 4. 마무리 (변화가 있을 때만)

```
python Record/site/build.py
git add -A
git commit -m "auto(<semester>): LMS 마감·제출 상태 동기화 (YYYY-MM-DD)"
git push
```
push 가 밀리면 `git pull --rebase` 후 다시 push.

**Artifact 재배포는 하지 마라 — 헤드리스 세션엔 Artifact 도구가 없다.** HTML 은 커밋만 해 두면 다음 대화형 세션이 올린다. 할일 앱은 md 를 직접 읽으므로 바로 반영된다.

### 실패 보고
1번(충돌)이나 2번(로그인)에서 멈췄으면 파일을 하나도 고치지 말고 `python auto/notify.py "⚠️ 자동점검 실패: <한 줄 사유>. 수동 확인 필요"` 후 로그에 사유를 적고 끝낸다.

## 5. 알림 (변화가 있거나 실패했을 때만)

`python auto/notify.py "<내용>"` — 짧게, 오늘 움직여야 하는 것만:
- `⚠️ <과목> <항목> — 오늘 HH:MM 마감, 미제출`
- `🆕 <과목> <항목> 개방 (마감 MM-DD)`
- `✅ <과목> <항목> 제출 확인`
- `📄 <과목> 새 자료 N개`

마감이 3일 이상 남은 미제출 항목은 적지 마라.

## 6. 로그

`auto/last-run.log` 에 한 줄 덧붙인다: `YYYY-MM-DD HH:MM <no-change | 변화 N건 반영 · push <해시> | 실패: 사유>`
